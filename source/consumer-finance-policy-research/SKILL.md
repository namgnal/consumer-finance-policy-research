# 消费金融政策研究工具

## 定位

本 Skill 是 Agent 与既有研究后端之间的薄适配层，负责：

- 把已确认的研究要求、网页链接、粘贴文字和附件转成后端契约；
- 管理材料草稿及异步研究任务；
- 校验操作句柄、附件路径、授权字段和响应结构；
- 只向 Agent 返回有界的业务视图，不透传后端 raw JSON。

本 Skill 不执行网页搜索、政策分析、模型推理或报告生成；这些能力属于研究后端。不要在 Skill 内重建第二套研究流程。

## 用户输出边界（最高优先级）

面向普通用户只说自然中文的任务理解、可修改计划、材料接收结果、研究进度、报告局限、报告结论和下载入口。不得在回复中展示或解释：

- 英文报告档位、权限枚举、内部状态值或后台字段名；
- 脚本命令、环境变量、本地目录、文件物化路径或排查过程；
- 草稿、任务、材料、授权和制品的内部句柄；
- 错误码、原始工具 JSON、重试参数或模型/后端调试细节。

工具执行失败时，把结果转成一句非空自然说明，任何终态都不得静默。附件无法唯一识别时只请用户重新上传一次，不猜路径、不列目录、不展示诊断命令。最终只按结果工具的安全投影交付：只要它返回 `可交付=true`，且 `报告正文` 或至少一个 `报告文件` 可读，就必须立即交付。正文是最低交付面；0、1 或多个 ready 文件都不能清空正文，每个合法且不歧义的 ready 文件独立保留，缺少另一种格式只作为局限提示。行动可行性、影响分析、事实保障、时序、语义一致性、需求覆盖、有用性、来源类别、权威层级、来源数量、交叉核验或覆盖度等内容质量问题统一降级为参考稿局限，不得再被解释成普通零交付。Agent 不得仅凭正文、文件或聊天内容自行绕过结果工具的机器字段、敏感信息、输出许可、跨任务/跨运行身份绑定、引用和制品完整性硬检查。只有结果工具明确返回 `可交付=false` 才进入无报告终态；即使如此也必须逐字转述它给出的非空自然 `交付说明`，不得把同时存在但并未造成阻断的来源缺口臆测成原因。

看到上传附件后，不得调用通用文件读取、文件转换、文档解析或复制命令，不得使用 `pandoc`、`cp`、解压工具，也不得创建附件的 Markdown 或文本副本。附件的唯一接收入口是本 Skill“收集附件”中的专用脚本；计划阶段只登记材料名称和用户说明，不自行解析正文，不声称“已经读完”，材料内容由用户确认后的研究后端统一处理。

研究计划直接完整展示在当前对话中，除非用户明确要求，不另建计划文件。计划只描述研究问题、证据边界、分析路径、拟交付内容和研究阶段核验项；不得把文件名、通用文件工具的临时解析结果或模型初读当成已经核验的政策事实。用户已给出主题、对象、资料边界、关注重点和交付用途时，计划后不得再列待确认问题。

部署配置、凭证、身份、渠道和验收边界仅供维护人员使用；需要维护时读取 [references/readme.md](references/readme.md)，普通研究对话不要加载或复述这些内容。

## 操作状态规则

`_draft_id`、`_material_ref`、`_authorization_context`、`_reference_item`、`_job_id`、`_artifact_id`、`_artifact_ids` 和 `_idempotency_key` 是不透明操作上下文：

- 可以保留在当前 Agent/工具上下文，用于同一任务的后续调用；
- 下划线只是命名约定，平台不会因此自动隐藏字段；Agent 向用户回复时只能引用工具返回的 `用户可见信息`，不得逐字回显工具 JSON、操作上下文或完整粘贴正文；
- 不解释内部格式，不作为认证凭证；
- 不写入长期记忆或跨用户复用；
- 同一会话后续出现“查看进度”“上个任务”或任何新消息时，优先从最近一次成功提交工具结果中恢复 `_job_id` 并查询原任务；找不到合法句柄时如实说明，绝不猜造；
- `operation_id` 只是兼容性调用标识，不参与默认幂等键；需要增删一批新材料时创建新草稿。

下载地址不是隐藏操作句柄。后端完成所有者校验后，短时 HTTPS 下载地址可以展示给当前所有者，但不得写入日志、长期记忆或数据库；过期后重新签发。

## 标准流程

### 提交前的交互前置条件

除非用户明确说“直接开始、无需确认、按默认开始”，调用本 Skill 提交研究前，Agent 先向用户展示完整的任务理解与研究计划。Agent 必须主动给出拟提纲，并补充 1—3 个有价值、用户尚未明确提出的研究角度；不要要求用户从零设计完整报告结构。同一轮最多提出 3 个真正影响范围或结论的澄清问题。计划应允许用户“接受并开始 / 只修改某一项 / 跳过确认按默认开始 / 先继续聊材料”。

先盘点用户已经明确的主题、范围、用途、侧重、排除项、材料边界和输出要求，不得重复询问。缺失信息能安全采用通用默认值时，直接在计划中说明默认值，不为确认而确认；只有不同答案会实质改变研究方向、证据边界或结论时才提问。若用户已经给出明确主题、报告用途与关注重点，并说明只使用公开资料，则无需澄清，只展示任务理解、研究计划和“确认后开始”的选项。

消费金融政策研究未另行指定时，采用以下安全默认值，不向用户反问：以持牌消费金融公司整体为主对象；只有公开证据充分、且分层会实质改变结论时，才补充银行系、互联网平台系或产业系差异，不询问用户是否分层。默认覆盖自营渠道、第三方/助贷合作、广告与直播投放、算法触达和消费者权益等完整业务链，并按证据强度与风险高低突出重点，不要求用户先选一个营销环节。以政策事实和合规边界为底座，同时平衡经营影响、风险、机会与现实建议。用户已经明确要求这些维度、公开资料和通用报告时，澄清问题必须为 0；不得把已有安全默认答案的问题包装成“可跳过”的问题。

计划阶段尚未检索或没有用户提供的可靠证据时，不得断言某项政策已经正式发布、正在施行、仍为征求意见稿、刚刚出台，也不得断言发布日期、生效日期、发布机关或废止状态。把这些未知时效事实列入“研究阶段核验项”，说明将以权威来源核验；不要把用户输入的文件名称自动当作政策状态事实。

用户局部修改后，先把修改合并进既有要求并重新展示完整计划；后续提交使用该完整版本，不能只传最后一次修改。默认成果是可供个人研读、内部讨论等场景复用的完整研究报告。会议只是可能用途，除非用户明确指定，不把成果锁成发言稿或 PPT，也不把“是否用于会议”或“是否需要一页纸”作为默认澄清问题。除非用户明确排除，第三方渠道、平台及合作机构应作为业务影响链的一部分纳入研究，而不是作为是否扩展研究范围的问题反问用户。政策事实、材料解读、行业影响、公司影响、趋势预测、风险机会和行动建议均按本次任务动态取舍，不机械套章。

每次完整计划都要给出自然中文的预计正文字符区间，并说明这是根据当前问题复杂度、材料量和证据密度作出的写作预估，用户可以在确认前直接调长或调短。不要把预估说成硬性承诺，也不要向用户显示英文档位。窄而聚焦的研究通常预估约 2500—5000 个正文字符，普通完整研究约 5000—9000 个，复杂材料的深度研究约 8000—15000 个；用户明确提出目标篇幅时，以其要求为准并写入完整计划。

用户确认“开始”、明确要求直接开始或接受默认计划后，提交唯一异步任务。提交成功后立即使用工具返回的 `立即回复用户` 作简短回执并结束当前 Agent 回合；不得在同一回合 sleep、循环查询或一直等待终态。研究后端会继续处理。宿主未提供可验证的自动跨轮推送能力时，除非宿主明确返回了真实后台任务/进度句柄，否则不得承诺“完成后自动发给你”。用户之后发送“查看进度”“上个任务”或任何新消息时，先恢复最近的 `_job_id`，只查询原任务，不重复提交。公开资料补搜、可访问来源替换、明确可重试错误的一次受控重试和参考稿降级都由系统自行完成；进度回复只告知现状，不提出会暂停任务的问题，也不等待逐篇网页授权。自主发现的某个公开页面不可访问时，换用其他可访问的权威来源；仍不足则记录报告局限并继续完成可供讨论的结果。付费、登录、内网或企业私有来源不得擅自取得权限，应跳过并继续使用已有合法材料；只有用户主动指定该来源为不可替代材料时，才说明其未被采用，不得让整个任务停在授权确认上。

### 周报、月报等周期报告

把月报、周报及其他按明确日期区间生成的报告统一视为“周期报告”，使用同一套托管研究、质量降级、安全正文、可用文件和参考资料交付合同。周报不得走比月报更弱的临时流程，月报也不得要求必须围绕单一政策。

- 用户可以只给出主题和周期，不上传任何材料。零上传是正常入口：不创建空草稿，不以“证据不足”拒绝，不要求用户先找资料；完成一次计划确认后，直接把用户原话、周期和关注范围提交给研究后端，由后端自主检索当期公开政策、数据、公司动态和其他可访问证据。
- 把用户明确写出的日期区间原样纳入完整任务要求。用户只说“本周、上周、某月、周报、月报”等相对周期时，不自行编造政策事实或日期；在计划中明确将由研究后端按任务基准日解析并核验报告期。无需为可确定的周期另行追问。
- 周期报告有用户材料时，把材料作为指定证据输入，同时允许后端自主补搜；材料围绕同一主题即可，不要求每份材料都对应同一个政策。材料或公开来源覆盖有限时仍按已有降级合同形成报告并说明局限，不在中途停工。
- 周报、月报及其他周期报告都必须在最终完成回复中交付报告实际引用或采用的参考资料；仅呈现给模型但未进入报告的背景候选不列出，不得只给报告文件而省略来源。

### 1. 收集附件

有附件且授权依据已由用户说明或可信渠道确认时，立即在收到附件的同一轮创建一个 `collecting` 草稿并逐项接收；同一批材料复用当前草稿。若附件来源与使用授权尚不清楚，只做一次最小授权确认，并在用户确认后的第一轮、研究计划确认前完成接收，不得猜测授权。研究计划的确认只控制封存和提交，不得为了先讨论计划而延迟已经具备合法授权依据的附件接收。

这是上传附件的唯一处理路径。不要先读取、转换、复制或总结文件，也不要调用 Agent 自带的文件阅读器；只按附件对象提供的完整原始文件名完成材料接收，不得用自己概括的材料标题、界面省略名或去掉扩展名的名称替代。用户确认完整研究计划前应先完成材料接收，但不得封存、提交任务或依据附件正文下结论。只有用户确认完整研究计划，或明确要求直接开始、无需确认、按默认开始，并确认材料清单后，才可封存当前草稿并提交唯一研究任务。

```bash
python scripts/create_material_draft.py
```

逐文件上传。先在本轮内部保留全部附件的完整原始文件名清单，再逐项调用一次接收脚本；向用户展示的简称与传给 `--filename` 的原名必须分开。脚本会在当前 Agent 的受控附件目录中短暂等待平台同步，并确定性找到唯一文件。不要先列目录、复制文件、设置附件根变量或猜测物化路径。

除 `create_material_draft.py` 与 `add_material_file.py --filename` 的规定调用外，材料接收阶段不得执行其他命令；不得使用 `python -c`、here-doc 或导入脚本内部函数绕过 CLI。脚本会在一次调用内有界等待附件同步，Agent 不得再次执行同一接收命令。部分材料成功时保留真实回执，只请用户重新上传未接收成功的文件；不得让已成功材料重传，不检查源码、不预热、不自行读取或改写报告。

```bash
python scripts/add_material_file.py \
  --draft-id <当前_draft_id> \
  --filename <用户上传时看到的原始文件名> \
  --permission-profile <已确认的内部权限档案> \
  --authorized-by <user_explicit|channel_verified> \
  --retention-mode <task_only|session_only>
```

权限档案的内部值见 [references/permission-model.md](references/permission-model.md)，不得向用户回显。只有收到成功状态并通过回执校验，才能用自然中文告诉用户该文件已正式接收：新建材料必须与本次完整原名、文件类型、精确字节数、授权和保留方式一致；相同字节已在当前草稿存在时，必须由精确字节数和内容摘要绑定，首次授权仍须合法，并如实展示首次保存的名称，说明“同一内容已正式接收，沿用首次授权和保留方式，未重复保存”。批量附件逐项报告成功清单和仅包含失败项的待重传清单；不得把“看见文件名”或临时读到正文说成正式接收成功。未找到或发现多个同名文件时停止路径排查，请用户只重新上传缺失项。单文件不超过 16 MiB，单草稿不超过 10 项；支持的扩展名见 `_bridge.py`。

封存前可以查询或删除：

```bash
python scripts/get_material_draft.py --draft-id <当前_draft_id>
python scripts/remove_material_file.py --draft-id <当前_draft_id> --material-ref <目标_material_ref>
```

达到上述完整研究计划确认条件并确认材料清单后封存。空草稿不会封存，`sealed` 草稿不能再增删：

```bash
python scripts/seal_material_draft.py --draft-id <当前_draft_id>
```

### 2. 收集用户主动提供的网页链接与粘贴文字

本节只处理用户主动发送、并要求作为指定材料使用的网页链接或粘贴文字。每项都先单独准备；不要让模型构造 `permission`、`source_urls`、`text_blocks` 或 `material_seeds`：

```bash
python scripts/prepare_reference_material.py \
  --kind <url|pasted_text> \
  --content <用户提供的完整链接或文字>
```

政府部门官网链接会在 `用户可见信息` 中返回 `授权状态=政府官网已自动确认`，并同时给 Agent 内部 `_reference_item`，无需打扰用户。其他网页及全部粘贴文字会在 `用户可见信息` 中返回四个清晰选择：`公开网页`、`本人合法取得`、`企业已授权`、`不使用该材料`。向用户回复时只转述 `用户可见信息`，不得展示、解释或改写内部 `_authorization_context`。

Agent、通用搜索工具或研究后端自行发现的 HTTP(S) 公开网页属于研究证据候选，不属于用户参考材料；不得对这些网页调用准备或确认工具，不得创建 `_reference_item`，也不得把它们加入 `reference_items` 后逐篇询问授权。Agent 提议“补充权威公开资料”后，用户回复“去搜吧”“可以”“按公开资料做”等明确同意，表示本次公开检索范围已经确认；应在当前唯一研究任务内由后端自行检索、换源和记录局限，不再询问网页授权类型，也不重新提交任务。只有报告交付后用户明确要求重新研究时，才进入显式重跑流程。

搜索发现付费墙、登录页、内网、临时签名链接或其他受限内容时，不得让用户替系统把它确认成公开网页，也不得使用其未读取正文；自主检索时跳过该来源，换用可访问来源，仍不足则由研究后端标记报告局限并继续。只有用户主动提供该链接或正文并要求作为材料使用时，才回到本节的单项授权流程；托管执行中自主发现且并非用户指定为不可替代材料的来源，不得中断任务等待授权。

V1 的单项粘贴文字上限为 20000 个 UTF-8 字节，同一次提交的粘贴文字合计上限为 40000 个 UTF-8 字节。原因是原文需要在本次 Agent 工具上下文中保留到任务提交；本实现没有把大段文字另存到持久状态。超过任一上限时不要截断，也不要跨轮携带全文，应请用户作为 TXT、DOCX 或 PDF 文件上传。

用户明确选择后调用：

```bash
python scripts/confirm_reference_material.py \
  --authorization-context <原样传入内部_authorization_context> \
  --choice <用户的中文选择>
```

只有 `用户可见信息.材料使用状态=可提交` 时，才保存内部 `_reference_item`；选择“不使用该材料”时直接从本次材料清单排除。一次研究把所有可提交的 `_reference_item` 原样组成 JSON 数组；附件、链接和粘贴文字合计最多 10 项，同一链接或文字只保留一项。授权状态、范围和许可依据均由服务端生成，Agent 不推断。

### 3. 启动研究

无附件时不创建空草稿，可直接提交主题，以及已经完成上述准备/确认的链接或文字。`policy_input` 为 1—20000 个字符，必须包含用户原话、已确认目标、重点、排除项、材料角色、比较对象、期限、输出要求，以及用户接受或调整后的 Agent 建议等完整任务要求；不得只提交本轮修改差异。普通完整报告省略 `output_spec`，由后端按证据量和结论密度自适应成稿，并生成 DOCX/PDF。

Agent 根据研究任务而不是为了凑字数选择内部篇幅策略：窄而聚焦的问题采用精要研究，通常的完整研究采用自适应完整报告，只有材料和问题确实复杂或用户明确要求全面深研时才采用深度研究。内部映射见 [references/api-spec.md](references/api-spec.md)，不得向用户显示英文档位。计划中的预计正文字符区间用于对齐预期，不自动变成硬性字数门槛；只有用户明确接受一个具体目标或另行提出篇幅时才传 `target_length`，只有用户明确提出硬性上下限时才同时传 `min_length` 和 `max_length`。内容完整、有决策价值后即可停止，不为凑字数重复材料。

脚本以完整、规范化后的业务请求生成默认 `idempotency_key`。随机 `authorization_id` 只用于服务端绑定，不进入业务指纹；`operation_id` 的变化也不改变业务键。复用原 `_reference_item` 的网络重试会恢复原任务。若同一内容被重新准备而换成新 `authorization_id`，后端会安全返回冲突，不创建第二个付费任务，也不消费新授权；此时继续查询原任务，不要盲目重提。

材料授权只证明用户有权把该链接或正文用于本次研究，不证明网页已被系统读取。自主发现的页面无法安全访问时应换源；仍不足则标记报告局限并继续，不要求用户下载上传。只有用户主动指定某一不可替代页面时，才可在最终说明中如实标记该材料未被采用。

只有当已有任务已到终态、且用户明确要求把完全相同的请求重新研究一遍时，才可额外传入 `rerun_after_job_id=<上一任务_job_id>`。脚本会先核验该任务真实存在、属于当前用户且已到终态，再用它生成一个新的幂等版本。同一次显式重跑及其所有重试必须复用同一个上一任务句柄。普通首次提交、重复确认、超时重试均不得传入该参数。

```bash
python scripts/submit_research_job.py \
  --policy-input "研究主题、范围、重点和约束" \
  --operation-id "policy-demo-001" \
  --draft-id <已封存且非空的_draft_id> \
  --reference-items '[<准备/确认工具返回的_reference_item>, ...]'
```

`reference_items` 只能来自准备/确认工具返回的内部 `_reference_item`。不得增加、删除或改写其中字段，不得自行传权限字典。没有链接或粘贴文字时省略该参数。提交脚本会按 `(kind, content)` 对集合稳定排序；同一批材料无论 Agent 以何种顺序收集，都会发送相同顺序的请求体并生成同一业务幂等键。

提交成功后必须先把 `_job_id` 保留在当前会话的工具上下文，再发送一次简短受理回执并结束本轮。不得紧接着调用进度脚本，不得以“我派了后台子任务”“完成后会自动通知”描述不存在的能力。用户无需重复确认计划；同一会话的下一条消息就是恢复原任务的触发器。

### 4. 查询与交付

```bash
python scripts/get_research_job_status.py --job-id <当前_job_id>
python scripts/get_research_job_result.py --job-id <当前_job_id>
```

每个用户回合最多查询一次。任务仍在等待或研究中时，直接回复当前进度并结束本轮，不 sleep、不按 `建议等待秒` 在同一回合继续轮询；下一次用户消息再使用同一 `_job_id` 查询。任务到达 `completed` 或 `completed_with_gaps` 时，立即在同一回合获取最终结果并交付。存在来源覆盖或内容质量局限但仍可交付时，把它们作为报告交付后的局限说明和可选完善方向，同时给出人工复核提示；不得将其改写成问题或暂停条件。向用户只使用自然中文状态。

结果工具返回报告正文、摘要、结论、影响、建议、材料采用情况、报告局限、可选完善方向、来源和报告文件等有界字段。`报告正文` 与 `参考来源` 都是后端及桥接层已经安全投影的交付面；`参考来源` 只含报告实际引用或采用的条目，仅呈现给模型但未进入报告的背景候选不在其中。不要从搜索候选、正文里偶然出现的网址、模型记忆或未采用材料另补来源，也不要向模型注入完整快照或内部证据表。

按结果工具返回的中文字段判断交付，不猜测后台状态：

- `质量检查通过=true` 且 `可交付=true` 时，按正式研究报告交付；非空 `报告正文` 直接展示，并为结果中每一个 `报告文件` 分别签发下载地址。0 个文件但正文非空、只有一个 ready 文件或缺少某一格式，都不改变报告已经交付；
- `可供讨论参考=true`、`交付状态=可供讨论参考稿`、`需人工复核=true` 且 `可交付=true` 时，把任务视为已经完成并交付参考稿。正文与 0、1 或多个文件均以结果工具实际返回为准，Agent 不得自行拼装或升级状态。先转述结果工具给出的 `交付说明`，再展示非空正文、全部可用文件、`报告局限` 和待核验项。若返回 `建议处理说明`，必须说明有问题的行动建议已从对话摘要删除、降级为待人工复核内容或不应直接执行；即使局限提到原稿曾有机器字段、敏感片段、结构或类型问题，只要结果工具已经标记可交付，就不得再次否定已完成安全重建的参考稿。不得称为失败，不得为了追求正式报告自动重跑或再次提交同一任务；
- Agent 不得维护或套用“允许交付的内容质量错误代码白名单”，也不得因新出现的内容质量码否定结果工具已经返回的 `可交付=true`。服务端来源证明、规范报告包、公开阅读投影、双 gate、摘要与清理扫描的可信性只由结果工具复验；Agent 不得自行放宽，也不得二次拦截；
- Agent 不得把缺失候选 schema/reason、双 gate 或内容降级凭证的异常结果当成旧版参考稿。即使正文、文件或其他候选布尔值仍在，也只服从结果工具最终给出的 `可交付`；不得自行补字段、猜版本或降级绕过；
- `报告局限` 和 `可选完善方向` 只用于报告交付后的透明说明，永远不是用户必须执行的补证动作。不得据此追问、等待确认、索要材料或链接、改写材料权限、缩小研究范围、改走通用联网搜索、绕过后端、把用户材料冒充公开网页或重新提交任务；
- `可交付=false` 时，必须逐字转述结果工具返回的完整 `交付说明`，不得删改、概括、补充或另作诊断；转述后立即结束该任务回复。不得从 `报告局限`、覆盖缺口、原始状态、错误代码、先前聊天或模型猜测另写“卡在哪了”“为什么”“接下来有几个选择”，也不得提供“补材料再研究／缩小范围／换通用搜索”的路线。如果结果同时返回 `用户无需操作=true`，不得再提问、索要授权或等待用户选择；不得自动重跑。

向用户转述时不要显示上述字段名、布尔值、后台枚举或错误代码，也不要显示包含内部英文标记的原始文件名；只使用结果工具给出的安全 `报告正文`、中文显示文件名、自然中文结论、`报告局限`、`可选完善方向` 和文件入口。报告正文篇幅只使用结果工具返回的 `报告正文字符数`，明确说“正文约 N 个字符”，不得按文件大小、页数、Word 词数或模型估算虚报。

### 5. 结果问答与下载

问答只读取已完成任务的不可变快照，不修改报告，也不生成修订版：

```bash
python scripts/ask_research_job.py \
  --job-id <当前_job_id> \
  --question "这项结论的原文依据和不确定性是什么？"
```

一旦结果达到上述任一可交付状态，就立即展示非空 `报告正文`，并遍历结果实际返回的每一个 `报告文件`：选择其 `_artifact_id`，同时提供所属 `_job_id`，分别签发下载地址；不要等用户再问“报告在哪”。结果没有文件但正文非空时，正文交付本身即为完成，不得等待或新建任务补文件。用户后续要求重新下载时也使用同一路径：

```bash
python scripts/create_artifact_download_grant.py \
  --artifact-id <目标_artifact_id> \
  --job-id <所属_job_id>
```

同一条完成回复中展示报告状态、实际正文字符数、非空正文、每个已成功签发的文件入口及有效期，并明确参考稿的人工复核要求。某个文件签发或发送失败时，保留并交付正文和其他成功文件，只如实说明该格式暂不可用；不得把整份报告改称未交付，也不得重新提交研究任务。不要保存下载地址。

在报告正文和可用文件入口之后，必须继续列出 `参考资料`，月报、周报、主题研究和用户材料研究一律相同：

- 只使用结果工具返回的 `参考来源`，保持其顺序；只列报告实际引用或采用的来源，不列仅呈现给模型但未进入报告的背景候选，也不从报告正文猜补链接。
- 每一项都必须逐字照抄工具给出的 `Markdown显示行`；不要自行拼接 Markdown、重新转义标题或文件名，也不要改写链接。
- `来源类型=网页` 时，`Markdown显示行` 只把安全标题绑定到后端核验并规范化后的完整原始页面 HTTP(S) URL；Agent 不得缩短、改写、根据标题或域名拼接，也不得用搜索结果页替代。
- `来源类型=用户文件` 时，`安全显示文本` 使用 HTML 数字字符实体阻止 Markdown/URL 解析，`Markdown显示行` 据此渲染后仍完整显示 intake ledger 中完整真实的原始文件名，并紧接“用户提供文件（无公开链接）”。它必须是不可点击普通文本；即使文件名看起来像 URL 或 Markdown 链接，也不得放入链接语法，不得为它杜撰公开地址。
- 若工具异常地没有返回可展示条目，仍保留 `参考资料` 标题并如实说明“来源清单请见报告文件附录；本轮可点击链接清单暂不可用”，不得从 raw evidence、正文或记忆编造来源；此情形不改变已经通过的报告文件交付状态。

## 错误处理

- 工具错误统一返回 `status=error`、`错误码`、`错误信息`，可能附带 `HTTP状态码`、`可重试`、`重试等待秒`。
- 失败或响应契约不完整时不得假称成功。
- 已到终态但无法交付文件时仍必须发送结果工具给出的非空自然说明；不得只结束工具调用而不回复用户。
- 只对明确标注可重试的错误重试；提交任务时保持完整业务请求不变。显式重跑若使用了 `rerun_after_job_id`，其重试必须复用同一个上一任务句柄。
- 详情见 [references/error-model.md](references/error-model.md)。

## V1 限制

- 不注册 `create_report_revision`；问答不会修改报告。
- `task_only` / `session_only` 是使用范围约束，不承诺自动物理删除。
- 不提供跨任务长期知识库。
- 每个部署环境均须分别验证附件字节映射、可信用户身份与会话隔离；离线契约测试不证明渠道集成已通过。
- `pilot_direct_env` 只用于私有单用户验收。它必须使用独立可轮换的试用凭证，不能替代生产环境的扣子开发者凭证代理；部署、迁移与退出步骤见 [references/readme.md](references/readme.md)。
