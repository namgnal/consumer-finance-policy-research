# 架构、配置与验收说明

## 架构定位

```text
用户（Web / 飞书）
        ↓
扣子 Agent：对话、附件入口、计划确认、结果解释
        ↓
本 Skill：12 个确定性薄适配工具
        ↓
研究后端：材料处理、核验、分析、报告、制品、任务与问答
```

本 Skill 不是另一条研究工作流，也不调用大模型。它只解决 Agent 调用既有后端时的文件、认证、参数、状态和错误契约。因此，Agent 可以配置 Skill；真正的多阶段政策研究流程仍在研究后端中执行。

## 工具清单

| 工具 | 作用 |
|---|---|
| `create_material_draft` | 创建空的 `collecting` 草稿 |
| `add_material_file` | 上传一个文件和一个完整权限 JSON |
| `remove_material_file` | 封存前删除一个材料 |
| `get_material_draft` | 查询材料清单与草稿状态 |
| `seal_material_draft` | 校验非空后封存草稿 |
| `prepare_reference_material` | 准备链接/粘贴文字；政府官网自动确认，其他来源返回用户选项 |
| `confirm_reference_material` | 根据用户明确选择闭合一次材料授权，不生成模型权限 |
| `submit_research_job` | 以请求体幂等键提交异步研究 |
| `get_research_job_status` | 查询粗粒度进度与恢复提示 |
| `get_research_job_result` | 获取有界的研究结果与制品引用 |
| `ask_research_job` | 围绕完成任务的不可变快照问答 |
| `create_artifact_download_grant` | 为当前所有者签发短时 HTTPS 地址 |

V1 不注册 `create_report_revision`，问答不修改报告。

## 状态与安全边界

### 操作句柄

`draft_id`、`material_ref`、授权上下文、`reference_item`、`job_id`、`artifact_id` 和幂等键是操作上下文，不是凭证。它们可以在当前 Agent/工具上下文中流转，以便继续同一任务，但不得：

- 展示给用户或要求用户手工管理；
- 写入长期记忆；
- 跨用户、跨会话或跨研究复用；
- 代替后端的 subject 与资源 ACL。

下划线字段只是内部命名约定，不会触发扣子平台自动隐藏。链接/文字工具把可转述内容单独放在 `用户可见信息`；Agent 回复用户时只转述这一对象，不得原样回显工具 JSON。

### 下载地址

短时下载 URL 只有在后端按当前所有者校验任务和制品归属后才可签发。地址可以展示给当前所有者，但必须 `no-store`，不写日志、不持久化，过期后重新签发。

### 身份

当前双头结构为：

| Header | 配置来源 | 作用 |
|---|---|---|
| `X-Research-Bridge-Key` | 开发者凭证 `RESEARCH_BRIDGE_KEY` | 服务桥接认证 |
| `X-Research-Subject` | 消费者凭证 `RESEARCH_SUBJECT` | 资源范围 subject |

消费者 `RESEARCH_SUBJECT` 目前不是经平台验证的正式多人用户身份。未完成 Web/飞书真实用户与会话隔离验收前，只允许受控单用户 Web 试用；多人模式应失败关闭，不能把消费者自行配置的值宣称为可信身份。

## 配置

本仓库不提供托管后端、平台项目编号或凭证。部署者需要准备符合 [API 契约](api-spec.md) 的研究服务，以及提供 `coze_workload_identity.requests` 的兼容运行时。普通 Python 环境仅可直接运行离线测试；正式工具不能省略宿主 SDK。

### 环境变量

| 名称 | 必填 | 说明 |
|---|---:|---|
| `RESEARCH_API_BASE_URL` | 是 | 自行部署的 HTTPS 研究后端；无默认值 |
| `RESEARCH_ATTACHMENT_ROOTS` | 按渠道 | 受控附件根目录，逗号分隔；建议显式指定最小范围 |
| `RESEARCH_CREDENTIAL_SKILL_ID` | 条件必填 | 本次安装的 Skill ID；多个同名凭证候选时显式指定 |
| `RESEARCH_CREDENTIAL_MODE` | 否 | 默认 `native_proxy`；受控单用户联调可显式选择 `pilot_direct_env` |
| `RESEARCH_PILOT_API_ORIGIN` | 仅试用模式 | 经部署者核对的 HTTPS 端点，必须与基础地址完全一致 |
| `POLICY_RESEARCH_PILOT_ACCESS_TOKEN` | 仅试用模式 | 独立、最小权限、可轮换的试用 bridge key |
| `POLICY_RESEARCH_PILOT_SUBJECT_ID` | 仅试用模式 | 不透明的单用户标识，不能当作正式多人身份 |

### 凭证与域名

1. 把 `RESEARCH_BRIDGE_KEY` 配置为开发者凭证，把 `RESEARCH_SUBJECT` 配置为消费者凭证。
2. 将 Skill 的允许访问域名设置为自己的研究服务域名；不把密钥写入源码、说明文档或命令示例。
3. 环境变量占位符按显式 `RESEARCH_CREDENTIAL_SKILL_ID`、运行时 `skill_id`、同名前缀下唯一候选的顺序解析，不包含任何原安装的编号。
4. 当前实现发请求前要求两个业务凭证/占位符均可解析。只有代理地址与身份票据、但没有对应占位符时会失败关闭；宿主的凭证注入行为必须单独验证。

```text
RESEARCH_API_BASE_URL=https://research.example.invalid
RESEARCH_CREDENTIAL_SKILL_ID=<your-skill-id>
```

上方域名仅作格式示例，不提供服务。工具输出的下划线字段不会自动隐藏，Agent 仍需遵守用户输出边界。

### 受控单用户联调

`pilot_direct_env` 是显式兼容模式，要求同时配置基础地址、匹配的 `RESEARCH_PILOT_API_ORIGIN` 和两个试用变量。缺值、来源不匹配或模式无效时在联网前拒绝请求；此模式禁止 HTTP 重定向。公开源码不等于公开运行实例：实例、运行环境和凭证仍应私有。联调结束后恢复默认模式并轮换、吊销试用凭证。公开版不会导入本地 `_dev_credentials.py`。

## 附件适配

`add_material_file` 默认只接收用户上传时看到的原始文件名。安装在扣子 Agent 的 `.skills` 目录时，桥接层会确定性推导该 Agent 自己的 Drive 根目录；其他渠道可用 `RESEARCH_ATTACHMENT_ROOTS` 显式配置受控根。解析器执行以下检查：

- 只检查每个受控根的直接子项，不递归扫描系统目录；
- 首次零匹配时在同一受控根和同一精确规则内有界等待最多 12 秒，兼容批量附件分批物化；安全冲突不会等待；
- 精确匹配原始文件名，或匹配扣子物化时添加的固定后缀，且必须只有一项；
- 不是 HTTP(S) URL、目录或符号链接；
- 扩展名在允许列表中；
- 新建材料上传给后端和展示给用户的名称仍是本次完整原始文件名，不使用物化后缀名；相同字节已存在时展示后端返回的首次保存名称；
- 文件非空且不超过 16 MiB。
- 新建材料的后端回执必须与实际上传的原始文件名、MIME、精确字节数、授权和保留方式一致；若相同字节已存在，则以精确字节数和 SHA-256 绑定本次内容，校验首次授权仍符合当前合同，并接受后端返回首次保存的规范文件名/MIME/保留方式，避免同一内容换名重传后陷入永久失败。

不同宿主的附件物化方式需要分别验证“文件对象 → 本地字节 → multipart 上传 → 后端回执”；离线测试不代表 Web、飞书或其他渠道的真实附件链路已通过。

## 草稿与任务规则

- 草稿状态只有 `collecting`、`sealed`。
- 同一批文件使用一个 `collecting` 草稿；封存前可增删，封存后不可变。
- 空草稿不封存；没有附件时直接提交研究。
- 月报、周报及其他按日期区间生成的报告统一走周期报告流程。用户只给主题和周期、零上传时也是完整合法入口：完成计划确认后直接提交，由研究后端自主检索公开政策、数据、公司动态和其他可访问证据；不得以“证据不足”为由要求用户先上传资料。周报与月报使用相同的托管执行、参考稿降级、安全正文、可用报告文件和参考资料交付合同。
- 周期报告有用户材料时，材料可以围绕共同主题而非单一政策；后端仍可自主补搜。提交的 `policy_input` 保留用户明确日期区间或相对周期，不让 Agent 擅自改成单一政策研究。
- 上传 multipart 恰好包含 `file` 和 `permission`，后者是完整 JSON 字符串。
- 只有用户主动提供并要求作为指定材料使用的网页链接和粘贴文字，才经过 `prepare_reference_material`；政府部门官网自动确认，其他来源由用户选择公开、自有授权、企业授权或不使用。Agent、通用搜索工具或研究后端自行发现的公开网页属于研究证据候选，不走 prepare/confirm，不进入 `reference_items`，也不逐篇向用户询问授权。
- 授权不等于网页已读取；自主检索的第三方页面不可达时由后端换用可访问来源，仍不足则作为报告局限记录并继续完成参考报告，不中途要求用户下载上传。只有用户主动指定的不可替代页面可以在最终说明中标记为未采用。
- 提交脚本只接收工具返回的 `reference_items`；Agent 不得生成 `permission`、`source_urls`、`text_blocks` 或 `material_seeds`。
- 附件、链接和粘贴文字合计最多 10 项；提交前查询草稿数量并合并计算，同一链接或文字只保留一项。粘贴文字单项最多 20000、同次提交合计最多 40000 个 UTF-8 字节，更多内容改用文件上传。
- 提交脚本按 `(kind, content)` 稳定排序 `reference_items`；同一材料集合的收集顺序不会改变 POST 请求体或业务幂等键。
- `policy_input` 为 1—20000 个字符。
- `output_spec` 是对象；CLI 参数使用 JSON 对象字符串。
- 默认 `idempotency_key` 由完整业务请求决定；复用原材料上下文的重试不会创建第二个任务。若重新 prepare 导致授权句柄变化，后端安全拒绝冲突并要求继续查询原任务，同样不会重复付费。
- 只有已有任务到终态且用户明确要求重新研究完全相同的请求时，才传入 `rerun_after_job_id=<上一任务_job_id>`；脚本先核验归属与终态，该次重试复用同一上一任务句柄。
- 异步状态为 `queued`、`running`、`completed`、`completed_with_gaps`、`failed`。

## 参考资料交付

- 结果桥接只消费后端已经安全投影的报告正文，以及 canonical `snapshot.source_list`；只返回报告实际引用或采用、且允许输出的来源。仅呈现给模型但未进入报告的背景候选不返回。缺少来源清单时不从 raw evidence ledger 猜链接或文件名；安全正文或任一已通过合同校验的报告文件仍可交付，本轮可点击来源清单如实标记为暂不可用。未采用搜索候选不得进入用户回复。
- 正文是最低交付面。只有后端显式 `verified` 或完整 `reference_candidate` 合同才进入交付；桥接层不从旧状态或可疑文件自行重建可信候选。进入可信交付后，0、1 或多个 ready 文件都不清空正文；DOCX/PDF 各自独立保留，缺失另一格式只提示局限。内容质量问题只进入参考稿局限，安全、身份绑定、引用和制品完整性硬错误仍失败关闭。若原 writer 正文曾含机器字段、敏感片段、结构或类型问题，只有后端 v3 已丢弃或清洗原稿、重建公开正文，并以 `candidate_authorization_origin=service_default|managed_post_corpus`、一致 schema/reason、双 gate、规范报告包正文哈希和语义摘要、hard scan clean、human projection clean 完整证明时，桥接层才交付重建稿；安全证据 ID 必须以非空、排序、唯一列表绑定数量，并与规范报告包 `evidence_ledger` 的 ID 集合精确相等，不安全引用排除数量必须是非负整数。未知、缺失或注入来源及不完整、伪造 metrics 均不能放行。出现 v3-only 字段、内容降级痕迹或未知内容码后，即使删除 schema/reason 或双 gate 也不能回退旧候选。桥接层按后端 40 字段报告包结构和相同 canonical JSON 规则重算 artifact-free `report_package_semantic_sha256`，材料/证据账本、正文、封面、附录、样式或结论篡改都会拒绝。
- 规范报告包正文可保留 E-DOC 等证据编号，公开阅读投影可改为具名引用；v3 只从 `delivery.final_report` 交付公开正文，不信任 snapshot 作为替代来源，且非空 snapshot 正文必须与 final report 相同。两面分别按规范正文哈希/字符数与公开投影字符数/clean 凭证校验，不要求 canonical/public 文本相等；公开正文还会本地扫描机器字段、错误码与敏感凭证，同长度替换不能绕过。v3 不维护内容质量错误码白名单，未来新增内容质量码可在完整服务端证明下交付安全摘要；无合格全文、权限不明、禁止输出、身份绑定或报告包完整性等明确硬码仍拒绝。
- 网页来源返回 `来源类型=网页` 和后端核验并规范化后的完整原始页面 HTTP(S) `链接`。桥接层只校验和保留该 canonical URL，不根据标题、locator 或域名重建链接，Agent 也不得再次改写。
- 上传材料返回 `来源类型=用户文件`、intake ledger 中的完整原始 `文件名`、空 `链接` 和“用户提供文件（无公开链接）”。桥接层将 Markdown ASCII 标点编码为 HTML 数字字符实体，生成不可点击且视觉上保真的 `安全显示文本`。文件名即使呈现 URL 或 Markdown 样式，也不能进入链接语法。
- 每项来源都带唯一可信的 `Markdown显示行`。Agent 在同一条完成回复中先给安全正文和所有可用文件入口，再列 `参考资料`，并逐字照抄这些行，不自行拼接 Markdown。月报、周报、主题报告和基于用户材料的报告不得省略这一步，也不得补写工具结果以外的来源。
- `可交付=false` 时，Agent 逐字转述结果工具的 `交付说明`；不得把来源缺口改写成根因，不得列“补材料、缩小范围、改走通用搜索”等选择，也不得自动重跑。`用户无需操作=true` 时不再向用户提问或等待授权。

## 验收顺序

### 1. 离线契约测试

```bash
python scripts/test_bridge.py
```

测试不访问网络，主要覆盖凭证失败关闭、路径与句柄校验、两字段 multipart、链接/文字授权投影、政府官网自动确认、用户投影与内部上下文分离、稳定业务幂等键、响应投影、错误映射和短时 URL 校验。运行结果只能证明脚本契约，不能证明云端、附件渠道或真实模型链路。

### 2. 受控单用户 Web 联调

建议用一份脱敏小文件完成一次端到端检查：

1. 创建草稿并获得真实回执；
2. 上传文件并确认后端材料数量；
3. 封存并提交一次研究；
4. 查询到终态；
5. 获取结果并签发下载地址；
6. 围绕结果做一次只读问答。

联调时保持完整业务请求不变以验证默认幂等；可故意更换 `operation_id`，确认后端仍返回同一任务。不要用 `rerun_after_job_id` 做普通重试。

### 3. 飞书与多人验收

部署到多人生产环境前单独验证：

- 飞书文件对象能否可靠映射为脚本可读字节；
- 不同飞书用户、群聊、私聊和线程是否得到正确 subject；
- 用户 A 无法查询、问答或下载用户 B 的草稿、任务和制品；
- 短时 URL 不进入聊天日志之外的持久层。

这些检查完成前，不应宣称对应部署或多人隔离已经通过验收。

## 当前 V1 限制

- 仅支持当前任务/会话材料，不提供长期知识库。
- `task_only` 和 `session_only` 不承诺自动物理删除。
- 报告修订未实现；问答只读。
- Web/飞书附件字节映射待实测。
- 正式多人可信身份与会话隔离待验收。
